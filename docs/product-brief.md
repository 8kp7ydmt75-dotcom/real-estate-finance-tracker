# Product Brief

## Problem

Small and mid-sized Indian builders often run project finance operations across Excel sheets, WhatsApp messages, site updates, vendor calls, and memory. That works early in a project, but it becomes risky as units, buyers, vendors, landowner allocations, and construction stages multiply.

Common risks include:

- Buyer collections not matching agreed sale value
- Vendor invoices and payments being tracked in separate places
- Project-wide costs being hard to allocate across units
- Landowner unit expenses and reimbursements being missed
- Margin conversations happening without a shared source of truth
- Audit trails being reconstructed after the fact

## Target Users

- Builder or developer: reviews project profitability, cash position, and inventory
- Accountant: tracks collections, vendor payables, invoices, payments, and audit notes
- Site engineer: connects work packages and vendor costs to project execution
- Sales/admin user: updates buyer status, receipts, handover dates, and unit details

## Main Workflows

- Create a project workspace
- Add developer and landowner units
- Record buyer receipts against sold units
- Record vendor invoices and payments at project or unit level
- Track landowner reimbursable expenses
- Review unit economics, cost allocation, and margin
- Monitor overdue vendor invoices and pending buyer dues

## Public Demo Positioning

The public repository uses mock data only. It is designed to demonstrate product thinking, India-specific real-estate finance workflows, and a full-stack implementation approach without exposing private project records.
